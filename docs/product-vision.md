# 실행 예산 설계

Aurora는 요청의 범위와 예상 소모량을 검토하고 실행 여부를 결정하는 작업 흐름을 목표로 한다.
예산 제한과 결과의 완성 여부를 별개로 다룬다. 아래 설계는 실제 모델 연결 이후의 계획이며 v0.1.0의 구현 기능이 아니다.

## 계산·추정·제한

| 항목 | 가능한 접근 | 한계 |
| --- | --- | --- |
| 입력 토큰 | 보낼 문맥과 도구 정의를 확정한 뒤 제공자의 토큰 계산 기능 사용 | 이후 도구 결과·추가 턴의 입력은 다시 계산해야 함 |
| 출력·추론 토큰 | 유사 작업의 실행 기록으로 범위 추정 | 실패·재시도·문제 복잡도를 미리 확정할 수 없음 |
| 생성 상한 | 제공자가 지원하는 출력 토큰 상한 설정 | 한도 도달 시 응답·작업이 미완성일 수 있음 |
| 전체 작업 예산 | 각 호출의 입력과 허용 출력을 예약하고 측정값 정산, 다음 호출 전 잔여 예산 검사 | 도구 비용·동시 실행·캐시 등 제공자별 계산 필요 |
| 기능 완료 여부 | 범위를 명시하고 테스트·검토 등 합의한 완료 조건으로 확인 | 사용 토큰 수나 모델의 자기 평가만으로 보장할 수 없음 |
| 계정 한도 비율 | 제공자가 공개한 검증 가능한 환산·한도 데이터가 있을 때 표시 | 토큰 수와 구독 잔여 %를 임의로 선형 환산하지 않음 |

## 계획하는 흐름

1. 입력한 요구사항과 작업 자료를 확인한다. 이 과정에 모델을 쓰면 계획 단계에도 비용이 발생한다.
2. 구현 범위와 제외 범위, 확인 가능한 완료 조건을 제안한다. 계획 단계의 예산과 본 작업 예산을 구분한다.
3. 예상 범위와 추정 근거, 불확실한 항목을 제시한다. 관측 기록이 부족하면 정확한 견적처럼 표시하지 않는다.
4. 승인된 범위에서 작은 단계로 실행한다. 출력 상한은 호출별로 적용하고 입력·도구 비용은 별도로 관리한다.
5. 실제 사용량과 검증 결과를 기록한다. 남은 예산으로 다음 호출을 허용할 수 없으면 멈추고, 범위 축소나 추가 예산을 선택받는다.

예를 들어 로그인 화면만 구현하고 인증 서버·계정 복구는 제외하는 식으로 범위를 정할 수 있다.
그 범위를 5,000토큰 안에 반드시 구현할 수 있다고 약속할 수는 없다. 한도에 도달하면 완료된 부분과 미완료 항목을 보고해야 한다.

모델 추천 역시 평가 데이터에 기반한 제안이다. 사전에 어떤 모델이면 반드시 성공하는지 아는 기능으로 취급하지 않는다.

## 현재 구현

v0.1.0은 문자 수 기반 입력 근사치와 등급별 고정 출력 범위를 표시한다.
v0.1.0에는 실제 토크나이저, 실행 기록 기반 예측, 모델 호출, 토큰 상한 강제, 단계별 실행 제어가 없다. 이후 main에 추가한 API 호출 경로는 아래에 구분한다.
직접 설정한 계획용 예산 대비 비율은 계산하지만, 계정 잔여량을 뜻하지 않는다.

## 참고

2026-10-19 확인한 OpenAI 공식 문서의 예시다. 다른 제공자에 그대로 적용되는 보장은 없다.

## main의 모델 역할 설정과 API 어댑터

내부 분석 모델과 실제 답변을 생성하는 모델을 독립적으로 설정한다.
OpenAI 초기값은 GPT-6 Luna / GPT-6.1 Sol, Claude 초기값은 Haiku 5.5 / Sonnet 5.5이다.
이 값은 시작 설정이며 계정별 접근 가능 여부를 보장하지 않는다. 실행 모델은 요청마다 다시 선택한다.

main에는 API 키를 이용한 내부 분석·텍스트 실행 어댑터가 추가되었다. 내부 분석은 작업 범위와 추천 모델을 반환하며, 정량 토큰 예측을 반환하지는 않는다.
호출별 생성 상한은 분석 2,048·실행 4,096토큰이고 입력은 별도이다. 이는 전체 작업 예산 제어가 아니다.
응답의 실제 사용량과 미완성 상태를 표시하고, API 오류를 자동 재시도하지 않는다.
단위·UI 테스트는 모의 응답으로 검증했으며 실제 키를 사용하는 라이브 호출은 아직 검증하지 않았다.
